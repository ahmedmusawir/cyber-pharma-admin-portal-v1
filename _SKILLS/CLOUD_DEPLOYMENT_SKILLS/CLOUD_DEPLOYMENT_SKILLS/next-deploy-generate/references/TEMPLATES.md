# Canonical Templates — Next Deploy Generate

These are battle-tested templates derived from successful DockBloxx (WooCommerce + Stripe ecom) and StarkReads (Stripe + Supabase SaaS) deployments. Every file generated by the next-deploy-generate skill MUST be based on these templates.

---

## Template 1: Dockerfile

3 stages. Stage 1 (deps) and Stage 3 (runner) NEVER change. Stage 2 (builder) adapts based on which secrets are build-time and which public vars exist.

### Full Template

```dockerfile
# --- STAGE 1: DEPENDENCIES ---
FROM node:18-alpine AS deps
RUN apk add --no-cache libc6-compat
WORKDIR /app

COPY package.json yarn.lock* package-lock.json* pnpm-lock.yaml* ./

RUN \
  if [ -f yarn.lock ]; then yarn --frozen-lockfile; \
  elif [ -f package-lock.json ]; then npm ci; \
  elif [ -f pnpm-lock.yaml ]; then yarn global add pnpm && pnpm i --frozen-lockfile; \
  else echo "Lockfile not found." && exit 1; \
  fi

# --- STAGE 2: BUILDER ---
FROM node:18-alpine AS builder
WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules
COPY . .

ENV NEXT_TELEMETRY_DISABLED=1

# >>> INSERT BUILD-TIME SECRET ARGs HERE <<<
# >>> INSERT PUBLIC VAR ARGs HERE <<<

RUN npm run build

# --- STAGE 3: RUNNER ---
FROM node:18-alpine AS runner
WORKDIR /app

ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1
ENV PORT=3000

RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs
EXPOSE 3000
CMD ["node", "server.js"]
```

### Stage 2 Insertion Rules

For each **build-time secret**, add:
```dockerfile
ARG SECRET_NAME
ENV SECRET_NAME=${SECRET_NAME}
```

For each **public var**, add:
```dockerfile
ARG NEXT_PUBLIC_VAR_NAME
ENV NEXT_PUBLIC_VAR_NAME=${NEXT_PUBLIC_VAR_NAME}
```

**`NEXT_PUBLIC_APP_URL` is ALWAYS present.** Order: secrets first, then public vars.

If there are ZERO build-time secrets, omit the secrets block entirely — only public var ARGs remain.

### Example A: No build-time secrets (Stripe + Supabase SaaS)

```dockerfile
# Stage 2 ARG/ENV block:
ARG NEXT_PUBLIC_APP_URL
ARG NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY
ARG NEXT_PUBLIC_SUPABASE_URL
ARG NEXT_PUBLIC_SUPABASE_ANON_KEY

ENV NEXT_PUBLIC_APP_URL=${NEXT_PUBLIC_APP_URL}
ENV NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=${NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY}
ENV NEXT_PUBLIC_SUPABASE_URL=${NEXT_PUBLIC_SUPABASE_URL}
ENV NEXT_PUBLIC_SUPABASE_ANON_KEY=${NEXT_PUBLIC_SUPABASE_ANON_KEY}
```

### Example B: With build-time secrets (WooCommerce ecom)

```dockerfile
# Stage 2 ARG/ENV block:
ARG WOOCOM_CONSUMER_KEY
ARG WOOCOM_CONSUMER_SECRET
ARG STRIPE_SECRET_KEY
ENV WOOCOM_CONSUMER_KEY=${WOOCOM_CONSUMER_KEY}
ENV WOOCOM_CONSUMER_SECRET=${WOOCOM_CONSUMER_SECRET}
ENV STRIPE_SECRET_KEY=${STRIPE_SECRET_KEY}

ARG NEXT_PUBLIC_APP_URL
ARG NEXT_PUBLIC_BACKEND_URL
ARG NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY
ENV NEXT_PUBLIC_APP_URL=${NEXT_PUBLIC_APP_URL}
ENV NEXT_PUBLIC_BACKEND_URL=${NEXT_PUBLIC_BACKEND_URL}
ENV NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=${NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY}
```

## Template 2: cloudbuild.yaml

Three steps: build, push, deploy. Two variants depending on whether build-time secrets exist.

### Template 2A: WITH build-time secrets

Use when the app has secrets needed during `next build` (e.g., WooCommerce SSG pages).

```yaml
substitutions:
  _REGION: "{REGION}"
  _SERVICE_NAME: "{APP_NAME}-prod"
  _NEXT_PUBLIC_APP_URL: "https://pending-initial-deploy"
  # >>> ADD: _NEXT_PUBLIC_{VAR}: "value" for each public var <<<

steps:
  # 1. Build Docker Image (with build-time secrets)
  - name: "gcr.io/cloud-builders/docker"
    entrypoint: "bash"
    id: "Build Image"
    secretEnv:
      # >>> LIST each build-time secret's generic env var name <<<
      - "WOOCOM_CONSUMER_KEY"
      - "WOOCOM_CONSUMER_SECRET"
      - "STRIPE_SECRET_KEY"
    args:
      - "-c"
      - |
        docker build \
          --build-arg WOOCOM_CONSUMER_KEY="$$WOOCOM_CONSUMER_KEY" \
          --build-arg WOOCOM_CONSUMER_SECRET="$$WOOCOM_CONSUMER_SECRET" \
          --build-arg STRIPE_SECRET_KEY="$$STRIPE_SECRET_KEY" \
          --build-arg NEXT_PUBLIC_APP_URL="${_NEXT_PUBLIC_APP_URL}" \
          --build-arg NEXT_PUBLIC_BACKEND_URL="${_NEXT_PUBLIC_BACKEND_URL}" \
          --build-arg NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY="${_NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY}" \
          -t "{REGION}-docker.pkg.dev/$PROJECT_ID/cloud-run-source-deploy/${_SERVICE_NAME}:latest" \
          .

  # 2. Push to Artifact Registry
  - name: "gcr.io/cloud-builders/docker"
    id: "Push Image"
    args: ["push", "{REGION}-docker.pkg.dev/$PROJECT_ID/cloud-run-source-deploy/${_SERVICE_NAME}:latest"]

  # 3. Deploy to Cloud Run
  - name: "gcr.io/google.com/cloudsdktool/cloud-sdk"
    entrypoint: "gcloud"
    id: "Deploy to Cloud Run"
    args:
      [
        "run", "deploy", "${_SERVICE_NAME}",
        "--image", "{REGION}-docker.pkg.dev/$PROJECT_ID/cloud-run-source-deploy/${_SERVICE_NAME}:latest",
        "--region", "${_REGION}",
        "--platform", "managed",
        "--allow-unauthenticated",
        "--service-account", "sa-{APP_NAME}-runtime@$PROJECT_ID.iam.gserviceaccount.com",
        "--set-secrets",
        "WOOCOM_CONSUMER_KEY={APP_NAME}-woocom-consumer-key:latest,WOOCOM_CONSUMER_SECRET={APP_NAME}-woocom-consumer-secret:latest,STRIPE_SECRET_KEY={APP_NAME}-stripe-secret-key:latest",
        "--set-env-vars",
        "NEXT_PUBLIC_BACKEND_URL=${_NEXT_PUBLIC_BACKEND_URL},NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=${_NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY}",
        "--memory", "1Gi",
        "--max-instances", "1",
      ]

# Build-time secret mapping: app-specific Secret Manager name → generic build label
availableSecrets:
  secretManager:
    - versionName: projects/$PROJECT_ID/secrets/{APP_NAME}-woocom-consumer-key/versions/latest
      env: "WOOCOM_CONSUMER_KEY"
    - versionName: projects/$PROJECT_ID/secrets/{APP_NAME}-woocom-consumer-secret/versions/latest
      env: "WOOCOM_CONSUMER_SECRET"
    - versionName: projects/$PROJECT_ID/secrets/{APP_NAME}-stripe-secret-key/versions/latest
      env: "STRIPE_SECRET_KEY"
```

### Template 2B: WITHOUT build-time secrets

Use when all secrets are runtime-only (e.g., Stripe + Supabase SaaS). Much simpler — no bash wrapper, no secretEnv, no availableSecrets.

```yaml
substitutions:
  _REGION: "{REGION}"
  _SERVICE_NAME: "{APP_NAME}-prod"
  _NEXT_PUBLIC_APP_URL: "https://pending-initial-deploy"
  # >>> ADD: _NEXT_PUBLIC_{VAR}: "value" for each public var <<<

steps:
  # 1. Build Docker Image (no secrets at build time)
  - name: "gcr.io/cloud-builders/docker"
    id: "Build Image"
    args:
      - "build"
      - "--build-arg"
      - "NEXT_PUBLIC_APP_URL=${_NEXT_PUBLIC_APP_URL}"
      # >>> ADD per public var: "--build-arg" then "VAR=${_VAR}" as separate items <<<
      - "-t"
      - "{REGION}-docker.pkg.dev/$PROJECT_ID/cloud-run-source-deploy/${_SERVICE_NAME}:latest"
      - "."

  # 2. Push to Artifact Registry
  - name: "gcr.io/cloud-builders/docker"
    id: "Push Image"
    args: ["push", "{REGION}-docker.pkg.dev/$PROJECT_ID/cloud-run-source-deploy/${_SERVICE_NAME}:latest"]

  # 3. Deploy to Cloud Run
  - name: "gcr.io/google.com/cloudsdktool/cloud-sdk"
    entrypoint: "gcloud"
    id: "Deploy to Cloud Run"
    args:
      [
        "run", "deploy", "${_SERVICE_NAME}",
        "--image", "{REGION}-docker.pkg.dev/$PROJECT_ID/cloud-run-source-deploy/${_SERVICE_NAME}:latest",
        "--region", "${_REGION}",
        "--platform", "managed",
        "--allow-unauthenticated",
        "--service-account", "sa-{APP_NAME}-runtime@$PROJECT_ID.iam.gserviceaccount.com",
        "--set-secrets",
        "STRIPE_SECRET_KEY={APP_NAME}-stripe-secret-key:latest,STRIPE_WEBHOOK_SECRET={APP_NAME}-stripe-webhook-secret:latest",
        "--memory", "1Gi",
        "--max-instances", "1",
      ]
```

### cloudbuild.yaml Key Rules

- Build-time secrets use `$$VAR` (double dollar — Cloud Build injects from secretEnv)
- Public vars use `${_VAR}` (single dollar — Cloud Build substitution)
- `--set-secrets` format: `ENV_VAR={app}-{secret-name}:latest` — left = generic, right = app-prefixed
- `--set-env-vars` format: `VAR=${_VAR}` — for public vars needed at runtime (omit if none)
- `availableSecrets` maps: `versionName` (app-specific path) → `env` (generic label)
- Template 2A: requires `entrypoint: "bash"` + `args: ["-c", |]` for the multiline docker build with secret injection
- Template 2B: uses simple `args` list — cleaner, no bash wrapper

## Template 3: deploy.sh

```bash
#!/bin/bash
set -euo pipefail

# ==================================================
# STARK FACTORY — App Deployment Script
# App: {APP_DISPLAY_NAME}
# ==================================================

# --- CONFIG (change these per app) ---
PROJECT_ID="{GCP_PROJECT_ID}"
REGION="{REGION}"
SERVICE_NAME="{APP_NAME}-prod"

# --- PUBLIC VARIABLES (change these per app) ---
NEXT_PUBLIC_APP_URL="{DOMAIN_URL_OR_PLACEHOLDER}"
# >>> ONE LINE PER PUBLIC VAR WITH VALUE OR REPLACE_ME <<<

# --- EXECUTION (do not modify below this line) ---
echo "=================================================="
echo "🤖 Stark Deployment Agent: Initiating Sequence"
echo "   Project: $PROJECT_ID"
echo "   Region:  $REGION"
echo "   Service: $SERVICE_NAME"
echo "   URL:     $NEXT_PUBLIC_APP_URL"
echo "=================================================="

gcloud config set project "$PROJECT_ID" --quiet

echo "🚀 Submitting Cloud Build..."
gcloud builds submit \
  --project "$PROJECT_ID" \
  --region "$REGION" \
  --config cloudbuild.yaml \
  --substitutions \
    _REGION="$REGION",\
    _SERVICE_NAME="$SERVICE_NAME",\
    _NEXT_PUBLIC_APP_URL="$NEXT_PUBLIC_APP_URL"# >>> ,\ per additional public var <<<

echo "=================================================="
echo "✅ Deployment Sequence Complete."
echo "   Service: $SERVICE_NAME"
echo "   URL:     $NEXT_PUBLIC_APP_URL"
echo "=================================================="
```

### deploy.sh Rules

- `NEXT_PUBLIC_APP_URL`: custom domain if known (e.g., `https://starkreads.cyberizedev.com`), else `"https://pending-initial-deploy"`
- One variable line per public var in the PUBLIC VARIABLES section
- One `,\` substitution trailing line per public var in `--substitutions`
- Everything below "EXECUTION" is identical for every app — never modify

## Template 4: init-app.sh

```bash
#!/bin/bash
set -euo pipefail

# ==================================================
# STARK FACTORY — One-Time App Setup
# App: {APP_DISPLAY_NAME} | Project: {GCP_PROJECT_ID}
# IDEMPOTENT — safe to run multiple times.
# ==================================================

PROJECT_ID="{GCP_PROJECT_ID}"
REGION="{REGION}"
APP_NAME="{APP_NAME}"

echo "=================================================="
echo "🤖 Stark Factory: Initializing $APP_NAME"
echo "   Project: $PROJECT_ID | Region: $REGION"
echo "=================================================="

gcloud config set project "$PROJECT_ID" --quiet
gcloud config set run/region "$REGION" --quiet

# --- ENABLE APIs ---
echo "📌 Enabling APIs..."
gcloud services enable cloudbuild.googleapis.com run.googleapis.com \
  artifactregistry.googleapis.com secretmanager.googleapis.com iam.googleapis.com
echo "   ✅ APIs enabled."

# --- ARTIFACT REGISTRY (shared across apps) ---
REPO_NAME="cloud-run-source-deploy"
echo "📦 Checking Artifact Registry..."
if gcloud artifacts repositories describe "$REPO_NAME" --location="$REGION" &>/dev/null; then
  echo "   ✅ Repo exists."
else
  gcloud artifacts repositories create "$REPO_NAME" \
    --repository-format=docker --location="$REGION" \
    --description="Docker repository for Cloud Run"
  echo "   ✅ Repo created."
fi

# --- CREATE SECRETS ---
echo "🔐 Creating secrets..."
# >>> FOR EACH SECRET, GENERATE THIS BLOCK: <<<
#
# SECRET_NAME="${APP_NAME}-stripe-secret-key"
# if gcloud secrets describe "$SECRET_NAME" --project "$PROJECT_ID" &>/dev/null; then
#   echo "   ✅ $SECRET_NAME exists."
# else
#   echo -n "REPLACE_WITH_ACTUAL_VALUE" | gcloud secrets create "$SECRET_NAME" \
#     --data-file=- --project "$PROJECT_ID"
#   echo "   ✅ Created $SECRET_NAME — ⚠️ UPDATE THE VALUE!"
#   echo "      Run: echo -n 'real-value' | gcloud secrets versions add $SECRET_NAME --data-file=- --project $PROJECT_ID"
# fi

# --- RUNTIME SERVICE ACCOUNT ---
RUNTIME_SA="sa-${APP_NAME}-runtime"
echo "👤 Checking runtime SA..."
if gcloud iam service-accounts describe "${RUNTIME_SA}@${PROJECT_ID}.iam.gserviceaccount.com" &>/dev/null; then
  echo "   ✅ Runtime SA exists."
else
  gcloud iam service-accounts create "$RUNTIME_SA" \
    --display-name="${APP_NAME} Runtime SA" --project "$PROJECT_ID"
  echo "   ✅ Runtime SA created."
fi

# --- BUILD SA BINDINGS ---
echo "🔑 Build SA bindings..."
BUILD_ID="$(gcloud builds list --project "$PROJECT_ID" --region "$REGION" --limit=1 --format='value(id)' 2>/dev/null || echo '')"
if [ -z "$BUILD_ID" ]; then
  echo "   ⚠️ No builds yet — re-run this script after your first deploy."
else
  BUILD_SA="$(gcloud builds describe "$BUILD_ID" --project "$PROJECT_ID" --region "$REGION" --format='value(serviceAccount)')"
  BUILD_SA_EMAIL="${BUILD_SA##*/serviceAccounts/}"
  echo "   Build SA: $BUILD_SA_EMAIL"
  # >>> FOR EACH BUILD-TIME SECRET: <<<
  # gcloud secrets add-iam-policy-binding "${APP_NAME}-{secret-name}" \
  #   --project "$PROJECT_ID" \
  #   --member="serviceAccount:${BUILD_SA_EMAIL}" \
  #   --role="roles/secretmanager.secretAccessor" --quiet
  echo "   ✅ Build SA bindings complete."
fi

# --- RUNTIME SA BINDINGS ---
echo "🔑 Runtime SA bindings..."
RUNTIME_SA_EMAIL="${RUNTIME_SA}@${PROJECT_ID}.iam.gserviceaccount.com"
# >>> FOR EACH RUNTIME SECRET: <<<
# gcloud secrets add-iam-policy-binding "${APP_NAME}-{secret-name}" \
#   --project "$PROJECT_ID" \
#   --member="serviceAccount:${RUNTIME_SA_EMAIL}" \
#   --role="roles/secretmanager.secretAccessor" --quiet
echo "   ✅ Runtime SA bindings complete."

# --- VERIFICATION ---
echo ""
echo "=================================================="
echo "🔍 VERIFICATION"
echo "=================================================="
echo "Secrets:"
gcloud secrets list --project "$PROJECT_ID" --format="table(name)" --filter="name:${APP_NAME}"
echo ""
echo "Runtime SA:"
gcloud iam service-accounts describe "${RUNTIME_SA_EMAIL}" --project "$PROJECT_ID" --format="value(email)" 2>/dev/null \
  && echo "   ✅ Exists" || echo "   ❌ NOT FOUND"
echo ""
echo "=================================================="
echo "✅ Init complete for $APP_NAME."
echo "   Next step: ./deploy.sh"
echo "=================================================="
```

### init-app.sh Generation Rules

- One secret creation block per secret (use the idempotent `if/else` pattern)
- Build SA bindings: one `gcloud secrets add-iam-policy-binding` per build-time secret
- Runtime SA bindings: one `gcloud secrets add-iam-policy-binding` per runtime secret
- If a secret is BOTH build-time and runtime, it appears in BOTH binding sections
- Secret values are always `REPLACE_WITH_ACTUAL_VALUE` — never real values
- The script tells the user how to update values after creation

## Template 5: DEPLOYMENT_CHECKLIST.md

Generate a pre-filled markdown checklist with the actual app name, domain, project ID, and region. No placeholders — every command should be copy-pasteable.

### Required Sections

**1. Pre-Flight**
- [ ] Files in project root: `Dockerfile`, `cloudbuild.yaml`, `deploy.sh`, `init-app.sh`
- [ ] Scripts executable: `chmod +x deploy.sh init-app.sh`
- [ ] Authenticated: `gcloud auth list`
- [ ] Correct project: `gcloud config get-value project` → should show `{PROJECT_ID}`

**2. One-Time Setup**
- [ ] Run `./init-app.sh`
- [ ] Update each secret with real values (commands pre-filled per secret)
- [ ] Verify secrets exist: `gcloud secrets list --project {PROJECT_ID} --filter="name:{APP_NAME}"`

**3. First Deploy**
- [ ] Run `./deploy.sh`
- [ ] If placeholder URL: copy the Cloud Run URL from output
- [ ] Update `NEXT_PUBLIC_APP_URL` in `deploy.sh`
- [ ] Run `./deploy.sh` again
- [ ] Verify app loads

**4. DNS + SSL** (if custom domain)
- [ ] Create domain mapping: `gcloud run domain-mappings create --service {APP_NAME}-prod --domain {DOMAIN} --region {REGION} --project {PROJECT_ID}`
- [ ] Get DNS records: `gcloud run domain-mappings describe --domain {DOMAIN} --region {REGION} --project {PROJECT_ID}`
- [ ] Add CNAME in DigitalOcean: hostname=`{SUBDOMAIN}`, value=`ghs.googlehosted.com.`, TTL=3600
- [ ] Wait 15-30 min for SSL
- [ ] Verify: `curl -I https://{DOMAIN}`
- [ ] Update `deploy.sh` with custom domain URL
- [ ] Final deploy: `./deploy.sh`

**5. Invoker Policy**
- [ ] Set access: `gcloud run services add-iam-policy-binding {APP_NAME}-prod --project {PROJECT_ID} --region {REGION} --member="allUsers" --role="roles/run.invoker"`
- [ ] Verify: `gcloud run services get-iam-policy {APP_NAME}-prod --project {PROJECT_ID} --region {REGION} --format="yaml(bindings)"`

**6. Done**
- [ ] App loads at custom domain with HTTPS
- [ ] All features work
- [ ] Secrets accessible at runtime
